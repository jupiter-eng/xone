# xginswagger

API documentation: mounts the documentation generated by [swag](https://github.com/swaggo/swag) as a Swagger UI on xgin's native `*gin.Engine`.

- A module of its own: the UI assets are compiled into the binary, which every production service should not have to carry
- A field that is not set keeps the value from the annotations and is overridden only when set; the title and version default to `XApp`'s
- Values that vary by environment, such as `Host`, live in the configuration: an integration address differs from production, while annotations are compiled in
- The mount prefix is configurable, and a malformed one fails startup

## Quick start

First run `swag init` to generate the `docs` package from the annotations, then register it in the routes:

```go
import (
	"github.com/gin-gonic/gin"

	"github.com/jupiter-eng/xone"
	"github.com/jupiter-eng/xone/xgin"
	"github.com/jupiter-eng/xone/xginswagger"

	"example.com/shop/docs" // generated by swag init
)

func main() {
	xone.MustRun(xgin.New().WithRoutes(func(e *gin.Engine) {
		xginswagger.Register(e, docs.SwaggerInfo) // mounted at /swagger/*any by default
		// ... business routes
	}))
}
```

Open `http://localhost:8080/swagger/index.html` (the actual path is `xginswagger.URL()`). The `XGinSwagger` block is optional.

## Configuration

```yaml
XGinSwagger:
  Host: api.example.com    # the address shown in the document; defaults to the annotations' @host, and with neither set the Swagger UI uses the current request's address
  BasePath: /api/v1        # the common prefix of every endpoint; defaults to the annotations' @BasePath
  Title: ""                # defaults to XApp.Name
  Description: ""
  Schemes: []              # defaults to empty: the annotations' @schemes is kept unless this is set
  URLPrefix: ""            # the prefix of the UI mount path, mounted at /swagger/*any by default; starts with / and does not end with /
```

- A field that is not set keeps the value from the annotations and is overridden only when set. The title and the version are
  the exception, taking the first of these that has a value:
  - Title: `XGinSwagger.Title` → `XApp.Name` → the annotations' `@title`
  - Version: `XApp.Version` → the annotations' `@version` (`XGinSwagger` has no version field)

## API

| Function | Description |
|---|---|
| `Register(e *gin.Engine, info *swag.Spec)` | Mounts the Swagger UI on engine; `info` is usually `docs.SwaggerInfo`, and nil mounts the UI without filling any metadata |
| `URL() string` | The actual path the Swagger UI is served at (including `URLPrefix`), for logging or redirecting |
| `DefaultConfig() Config` | The defaults: every item empty, so anything not configured keeps what the annotations say |

## Notes

- `Register` may be called at any time before `Start` and reads the final configuration.
- `URLPrefix` is either empty or starts with `/` and does not end with `/`; a malformed one fails startup (`Register` mounts with the defaults first, and the error is reported by the start hook).
- The metadata is filled on the first visit to the document, because `XApp` is only read by `xone.Run`'s start hooks.
- **Several engines may mount the UI on the same `*swag.Spec`** (a public server and an admin one, which is what
  `xgin`'s `WithConfig` is for): that spec is the one swag registers globally, so the filling of each is kept
  apart from the other's reads. They read the same `XGinSwagger` block, so whichever fills first fills the same
  values.
